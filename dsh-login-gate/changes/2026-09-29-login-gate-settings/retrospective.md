## 做得好的

1. **跨面契约对账测试**（contract-e2e：真签发者/真落盘/client↔server 同场对账）挡住了契约漂移类缺陷，是全波最大质量资产。
2. **测试环境实测抓出高危认知偏差**：tester F-1 实测推翻「改端口必须重启」的分析假设（真实宿主 re-apply 即时生效），促成 R-16 用户重裁语义——单测假缝结构性看不到这类缺陷。
3. 修复环纪律：F1 类安全 finding 全部修因不修症状（e.message 插值源头切断而非改文案），每轮 scoped re-review 收口。
4. SDD deferred 清单全程可追溯，终审 17 项分诊零失联。

## 教训（lessons / 复盘改进）

1. **分析断言要标注验证边界**：scout-b「reconcile 是否重跑 apply 无证据」被写成「端口必须重启」的设计前提——推断当结论用，R-11 因此建在错误地基上，靠 tester 实测才翻正。今后：凡 NEEDS_CONTEXT 类未验证断言进设计，必须显式标「待实测」，并把实测排进验证卡（本次由 Task 14 捡回，教训=验证卡设计要盯"设计前提"而不只盯"行为验收"）。
2. **共享仓多会话并行成常态**：R-9 插提交隔离触发 4 次（review-package 必须钉我方提交父提交）；`.gitignore` 等他会改动全程零裹挟。派发面 git 卫生铁律（只 add 分域文件）应成为共享仓默认。
3. 目标快轮会造成时间误估（曾把 4 分钟当 20+ 分钟发过早点名）——判停滞先 `date` 校时，已入 ledger。
4. 门禁格式语义有隐性门槛（gate-phase0 半角问号/章节名前缀、gate-phase1 过渡声明词面）——转录与文档生成要先读 gate 正则口径，避免空转重跑。
